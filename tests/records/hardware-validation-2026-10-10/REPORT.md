# UNIUBI6913 SDK 0.2.0 历史实机指令验证

> 历史记录：0.3.0已移除F9、F8、F6、F7、C6；当前0.5.0保留AF/E1/E8并移除D0，共15类命令，标定/SN接口仅完成离线验证。下文17类命令及JSON均是0.2.0的原始测试证据，不代表当前功能清单；当前实机脚本仅保留只读状态查询。

日期：2026-10-10。SDK 0.2.0，调试板GD32C113，串口 `/dev/cu.usbmodem5C843882941`，4 Mbps/8N1。扫描ID1～6，仅ID1响应；电机版本V1.2.193，编码器类型3（MT6826S）。

**17类SDK命令均已实机执行，但不是全部验收通过：F6保存后参数不持久化，F7恢复出厂未观察到两个测试增益恢复。** 四种模式完成使能态正负小指令和失能测试；由于采用低限矩和短时间激励，不作为位置、速度跟踪精度或输出扭矩标定验收。

测试调用编译后的实际SDK C函数，使用SDK的A8发送回调、A0/AC字节流解析和电机反馈解析，Python仅提供串口I/O、断言和记录。没有用Python协议构帧替代SDK，没有修改或烧录调试板/电机固件。用户明确确认空载固定、允许附近±2.9°运动，并允许设零及恢复出厂覆盖配置。发送日志实际覆盖：AE、C6、CB、E9、EF、F0、F1、F4、F5、F6、F7、F8、F9、FB、FC、FD、FE。

## 运动记录

运动开始输出位置0.00460434 rad。主机守护阈值为相对起点±0.035 rad、速度绝对值0.15 rad/s，并检查故障、电压及完整状态温度；这是反馈驱动的软件守护，不是硬件限位。实际记录366条运动状态，最大绝对位置偏移0.00122356 rad（约**0.0701°**），最大反馈速度绝对值约0.01686 rad/s；未触发守护停止，记录中没有观察到故障位。

位置模式速度限幅0.04 rad/s；速度模式扭矩限幅请求0.2 Nm；位置模式速度环输出和积分限幅、PD输出限幅均临时设为0.2 Nm。各模式两段激励后均发出停止/归中目标，再失能确认。以下位置均为设零之前的坐标：

| 模式 | 正向/负向目标 | 两段结束位置（rad） | 两段结束Iq目标（A） |
|---|---|---|---|
| 位置 | 0.016604 / −0.007396 rad | 0.005783 / 0.005095 | +0.115686 / −0.062222 |
| 速度 | +0.02 / −0.02 rad/s | 0.005248 / 0.005121 | +0.031588 / −0.009655 |
| 扭矩 | +0.015 / −0.015 Nm | 0.005194 / 0.005185 | +0.007939 / −0.007939 |
| PD | 0.016604 / −0.007396 rad | 0.005221 / 0.005167 | +0.019710 / −0.021910 |

低限矩下位移很小；这些结果支持指令进入控制链路及正负反馈响应，不证明稳态精度、带载能力或额定性能。运动日志的`PASS`明确限定于使能态收发、有效反馈和守护阈值检查。

## 异常及源码核对

1. **F6不持久化**：写入3.125的小端值`00 00 48 40`，F9确认；发送F6等待约0.8秒后C6重启，读取变为`00 00 40 40`（3.0）。本地电机固件`mtp/mtc_main_function.c::param_control_()`注明用户OD页已重新分配，F6不再写Flash。SDK发送层不能替固件实现持久化，公共头和README已注明。
2. **F7未恢复测试增益**：先写位置Kp 3.125（0x6065）和速度Kp 1.125（0x606D），各自F9确认；F7应答后等待1秒、重新发现节点，再读取，两项仍是测试值。随后主动清除临时值。当前本地源码依赖Factory页加载和反序列化，页无效等失败不在标准ACK中体现；没有读取设备Flash，不能断言具体是出厂页缺失、无效还是不含这些条目。本地工作区也不必然等同已烧录镜像。
3. **区分复位与恢复出厂**：配置日志`baseline_changes`比较的是整个配置阶段起点，其中0x6068从约4.998856变19、0x6070从约29.999239变48.000004发生在包含C6的阶段，不能据此归因F7。后续脚本增加F7前单独快照。最终清理已把上述限幅恢复到阶段起点值。
4. **复位主动通知**：第一次失能态测试收到`01 C0 C1 02 01 03 00 00 00 00 00 00`，脚本将SDK的`EUNSUPPORTED`当作致命错误。C0不属于当前SDK反馈类型；脚本已改为保留事件后继续匹配，之后复位/重连通过。首次失败日志保留，不掩盖。
5. `0x6143`读值0；本地实现涉及标定触发，不能仅凭历史名称`Is_Calibrated`推断标定失效。本次没有写该字段启动标定。

## 最终设备状态

最终单独进行清理与全量15项读回验证，见`final-state.json`：

- ID1，模式1（位置模式），补偿位127，失能（状态字0）。
- 15项可读参数与运动测试前快照逐字节一致，包括位置Kp=3.0、速度Kp=1.0；临时增益和限幅已清除。
- 新机械零位保留，输出位置0 rad，输出速度约0.00000345 rad/s，Iq目标0 A。
- 故障寄存器0x6142=0，母线47V，NTC约29.65°C。
- 由于F6不持久化，恢复的运行时参数不代表已写入Flash；本次仅对EF零位和FB ID验证过软件重启保留。
