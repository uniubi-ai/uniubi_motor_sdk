# CAN FD 协议与数据说明

SDK 使用标准 CAN FD 数据帧，支持 ID1～6。常规应用使用公共 API 完成构帧与解析；下列布局用于适配 CAN FD 驱动和排查通信问题。

支持命令：AE（PD/MIT）、AF（自动标定）、CB（标准状态）、E1（标定完成标志）、E8（SN）、E9（版本）、EF（设零）、F0（模式）、F1（扭矩）、F4（速度）、F5（位置）、FB（ID）、FC（使能）、FD（失能）、FE（完整状态）。

## 请求布局

标准 CAN FD 数据帧，仲裁 ID `0x000`，载荷 64 字节：

| 字节 | 内容 |
|---|---|
| 0 | 主机 deviceId，固定 `0x00` |
| 1 | cmdCode |
| 2～61 | ID1～ID6 六个槽位，每槽 10 字节；偏移 `2 + (id-1)*10` |
| 62～63 | 预留零 |

除 PD 外的命令在选中槽的第 10 字节重复写 cmdCode，未选中槽为零。PD `0xAE` 的整个槽都是运行数据，没有尾部命令字节，不存在忽略槽。

| 命令 | 槽内容（全部小端） |
|---|---|
| FC/FD/EF/CB/FE/E9/AF/E1/E8 | 9 个 FF + 命令码 |
| F0 | 模式字节 + 8 个 FF + F0；模式 0速度/1位置/2扭矩/3PD |
| F4 | uint16 速度 + uint16 扭矩限幅 + 5 个 FF + F4 |
| F5 | uint16 位置 + uint16 速度限幅 + 5 个 FF + F5 |
| F1 | uint16 扭矩 + uint16 D轴零目标(8000) + 5 个 FF + F1 |
| AE | uint16 位置、速度、Kp、Kd、前馈扭矩，共 10 字节 |
| FB | 新 ID + 8 个 FF + FB |

F1 第二字段为 D 轴电流目标，SDK 固定编码为零，不提供非零 D 轴电流设置接口。

## 标定与身份查询

- **AF**：槽内9个FF加AF；普通12字节状态应答，不含流程完成标志。固件可能自动驱动并保存标定数据。
- **E1**：请求同上述简单帧；回复48字节，byte8～9小端完成位图，其他业务字节保留。
- **E8**：32字节回复，byte0设备ID、byte1=E8；byte2产品类型；byte3/4/5主/次/修订版本（不同于E9）；byte6～7小端年份，8月、9日；byte10～25为16字节SN；byte26 MCU类型；byte27～30保留；byte31必须E8。

E1完成标志的当前固件映射：bit0电角度零点、bit1齿槽、bit2第二编码器、bit3预留、bit4电流增益、bit5旧电角度补偿、bit6磁编码器、bit7摩擦、bit8 CSA温漂、bit9 L/R辨识。SDK原样保留全部16bit；未完成位无法区分未标定、进行中和失败。

## 量化

| 字段 | 范围 | 零点 | 非零取整 |
|---|---|---|---|
| 位置 | −12.5～12.5 rad | 0x8000 | 最近整数，正好一半取偶数 |
| 速度 | −65～65 rad/s | 0x8000 | 同上 |
| 扭矩/前馈扭矩/反馈扭矩 | −100～100 Nm | 0x8000 | 同上 |
| Kp | 0～500 | 0 | 同上 |
| Kd | 0～5 | 0 | 同上 |
| 速度/位置命令的 limit | 0～100，单位随命令 | 0 | 向零截断 |

编码公式：`raw = (value-min)/(max-min)*65535`，再按表取整。解码：零点码单独还原为 0，其他按 `min + raw/65535*(max-min)`。SDK 将 C `float` 输入提升为 `double` 完成量化计算。limit 使用向零截断，例如输入 2 编码为 1310（小端字节 `1E 05`）；取整差异可能产生一个量化单位的偏差。

## 回复

按目标节点 ID 筛选仲裁 ID 和 byte0。byte1 是回复命令。

- **标准状态 12 字节**：byte2～3 输出位置；4～5 输出速度；6～7 输出扭矩；8 预测温度（减40°C）；9 状态位；10 母线电压 V；11 本机ID（兼容旧固件填零）。SDK接受公共控制命令、CB查询及遗留运行 `0x00` 的状态回复。
- **FE 完整状态 48 字节**：byte2 起连续 11 个 float32，依次是 Iq目标、Iq测量、Id目标、Id测量、位置目标、B相电流、C相电流、输出轴速度、电机侧机械角度、输出位置、电机NTC温度；46 运行模式；47 补偿位图。模式和补偿字段是否有效取决于目标固件；不支持这些字段的固件可能返回零，不能据此判定实际模式。
- **E8 身份 32 字节、E1标定完成标志**：按上节解析，反馈种类为IDENTITY/CALIBRATION，不落入普通状态解析。
- **E9 版本 12 字节**：byte2 patch、3 minor、4 major、5电机侧编码器类型，直接按无符号字节解释，不作 BCD 解码。

完整状态拒绝 NaN/Inf，未知命令拒绝解析。解析成功不代表某次请求成功匹配，事务与超时由应用处理。不能用“发送回调成功”代替设备确认。

设备自主重启仍可能推送0xC0启动通知；该类型返回`U6913_EUNSUPPORTED`，调用方应记录后继续等待目标查询回复。

标准状态bit0为硬件使能，bit1～7分别为母线电压异常、过流、过温、过速、编码器故障锁存、预驱故障锁存、上电母线等待超时；公共头提供掩码。bit0不等于状态机就绪，bit1～4的已上报事件可能被固件清除，不应将后续零状态误当成故障原因已消除。FE本身不含这些状态位或母线电压，运行监控应同时查询CB。

## 接入检查

首次连接时确认 CAN FD 位时序、BRS、节点 ID 和反馈长度。先查询版本及状态，再在允许的运动范围内验证模式切换、使能和失能。多节点应用需统一组织 PD 六槽目标；应用负责断线超时、停机、设零和更改 ID 后的状态确认。
