# 协议基线与编码约定

## 来源及适用范围

核对日期：2026-10-10。当前SDK 0.5.0对应项目自研协议，非智身 `zhishen` 协议。支持15类命令：AE、AF、CB、E1、E8、E9、EF、F0、F1、F4、F5、FB、FC、FD、FE。F9、F8、F6、F7、C6、D0已从公共接口、构帧、SDK发送入口和反馈解析中移除。

对照资料包括用户提供的 `UNIUBI6913_关节电机使用说明书_V0.5.md`、调试板 `motorTools_gd32c113` 提交 `8a5ff493d9824c5d998d37a28fffb3f5e40cfa92`，以及 `src/core/motor_canfd_test` 子仓 `new_board_protocol` 分支提交 `b7675beabca6f4181768e08833125e436b482926`：

- `joint_motor/joint_motor_cmd.py`：命令码、模式码、六槽载荷、PD `0xAE`、F1 扭矩语义。
- `joint_motor/data_mapping.py`：量程、零值、round 与 limit 截断公式。
- `joint_motor/feedback_parser.py`：标准/完整状态及版本回复布局；核对时该文件已有本地修改，将完整状态 byte46/47 从预留标注为模式/补偿位图，并新增模式返回值。本 SDK 按此工作区定义原样暴露这两个字节；旧固件仍可能将它们作为预留零，不能据此判定旧固件实际模式。
- `board/can_motor.py`：标准帧发送 CAN ID `0x000`；UART 调试板封装不属于电机载荷。
- `config/CANFD_通信协议文档 (1).txt`：历史协议背景、CAN FD 参考位速率、参数及 CAN ID 设置说明。

源码中部分 docstring 仍写 72/81 字节串口帧、旧扭矩量程或 MSGID。这些描述不用于确定 CAN 数据长度和映射常量。核心构帧输出 **64 字节原始 CAN 数据**；直连 CAN 使用它，调试板适配将它进一步封装为81字节带CRC的A8请求。

## 手册与既有实现的差异

1. 文件名 V0.5，正文标题和版本记录为 V0.3；当前版本编号待资料维护方统一。未修改原始手册。
2. **FE byte30～33**：旧 Python 字段/注释称电机速度，产品说明书明确为输出轴速度。SDK 0.2.0 使用 `output_velocity_rad_s`，不乘除减速比。byte42～45 按手册改为电机 NTC；普通状态 byte8 为预测温度。
3. **limit 取整**：手册要求 round，例如2→1311（`1F 05`）、1→655（`8F 02`）；现有 `map_limit_to_raw` 使用截断，分别得到1310（`1E 05`）、655。SDK暂保留已有编码以维持与现有工具一致；差异最多1 LSB（100/65535），应在正式发布时统一手册、上位机和固件契约，不能声称所有手册示例逐字节一致。下表描述的是当前 SDK 行为。
4. **E8 请求**：手册写64字节六槽查询，现有 `build_read_sn_command` 使用12字节紧凑广播请求，不含单节点槽寻址。0.4.0核对本地电机固件 `canfd_extract_slot_command`、`canfd_validate_slot_command`、`canfd_protocol_parse` 的E8分支后，使用手册规定的64字节级联格式，避免广播语义。SN构帧不与该旧Python构帧器逐字节对照，改用六槽黄金格式测试；2026-10-10已在ID1/V1.2.193实机验证E8级联查询，ID1→2→1的SN一致，详见[复测报告](hardware-retest-v0.5.0-2026-10-10/REPORT.md)。
5. **F1第二字段**：手册明确是Id（A），上位机历史注释描述不一致。当前SDK只发零目标，新增非零Id控制前须核对电机固件。

产品资料规定仲裁ID与设备ID对应，标准状态byte11也为本机ID；解析器仍兼容旧固件byte11为零，通过仲裁ID及byte0校验归属。API按新手册暴露FE模式码、补偿位图及E9编码器类型；旧固件可能对新增字段回零。

## 请求布局

标准 CAN FD 数据帧，仲裁 ID `0x000`，载荷 64 字节：

| 字节 | 内容 |
|---|---|
| 0 | 主机 deviceId，固定 `0x00` |
| 1 | cmdCode |
| 2～61 | ID1～ID6 六个槽位，每槽 10 字节；偏移 `2 + (id-1)*10` |
| 62～63 | 预留零 |

普通特殊/配置命令在选中槽的第 10 字节重复写 cmdCode，未选中槽为零。PD `0xAE` 的整个槽都是运行数据，没有尾部命令字节，不存在忽略槽。

| 命令 | 槽内容（全部小端） |
|---|---|
| FC/FD/EF/CB/FE/E9/AF/E1/E8 | 9 个 FF + 命令码 |
| F0 | 模式字节 + 8 个 FF + F0；模式 0速度/1位置/2扭矩/3PD |
| F4 | uint16 速度 + uint16 扭矩限幅 + 5 个 FF + F4 |
| F5 | uint16 位置 + uint16 速度限幅 + 5 个 FF + F5 |
| F1 | uint16 扭矩 + uint16 D轴零目标(8000) + 5 个 FF + F1 |
| AE | uint16 位置、速度、Kp、Kd、前馈扭矩，共 10 字节 |
| FB | 新 ID + 8 个 FF + FB |

F1 第二字段在现有代码中仍有遗留命名，SDK 不暴露非零 D 轴激励接口。当前对外SDK不提供对象字典参数读写。

## 标定与身份查询补充依据

本地只读核对 `/Users/panhuijuan/motor/motorDriver_gd32e518_app/mtp/communacation_canfd.[ch]`：AF调用`AutoCalib_Start()`，E1使用专用打包函数，E8使用`canfd_protocol_pack_serial_number()`。这份工作区不必然等同设备V1.2.193镜像。没有更改或烧录固件，也没有调用真实AF。

- **AF**：槽内9个FF加AF；普通12字节状态应答，不含流程完成标志。固件可能自动驱动并保存标定数据。
- **E1**：请求同上述简单帧；回复48字节，byte8～9小端完成位图，其他业务字节保留。
- **E8**：32字节回复，byte0设备ID、byte1=E8；byte2产品类型；byte3/4/5主/次/修订版本（不同于E9）；byte6～7小端年份，8月、9日；byte10～25为16字节SN；byte26 MCU类型；byte27～30保留；byte31必须E8。拒绝把旧注释的`E8 E8`当作合法设备帧头。

E1完成标志的当前固件映射：bit0电角度零点、bit1齿槽、bit2第二编码器、bit3预留（旧版本曾为动力学辨识）、bit4电流增益、bit5旧电角度补偿、bit6磁编码器、bit7摩擦、bit8 CSA温漂、bit9 L/R辨识。SDK原样保留全部16bit；未完成位无法区分未标定、进行中和失败。

## 量化

| 字段 | 范围 | 零点 | 非零取整 |
|---|---|---|---|
| 位置 | −12.5～12.5 rad | 0x8000 | 最近整数，正好一半取偶数 |
| 速度 | −65～65 rad/s | 0x8000 | 同上 |
| 扭矩/前馈扭矩/反馈扭矩 | −100～100 Nm | 0x8000 | 同上 |
| Kp | 0～500 | 0 | 同上 |
| Kd | 0～5 | 0 | 同上 |
| 速度/位置命令的 limit | 0～100，单位随命令 | 0 | 向零截断 |

编码公式：`raw = (value-min)/(max-min)*65535`，再按表取整。解码：零点码单独还原为 0，其他按 `min + raw/65535*(max-min)`。SDK C `float` 输入先提升为 `double` 计算，与 Python 接受同一个 binary32 数值时逐字节一致。扭矩和前馈扭矩保留独立常量，便于未来协议分离。

## 回复

按目标节点 ID 筛选仲裁 ID 和 byte0。byte1 是回复命令。

- **标准状态 12 字节**：byte2～3 输出位置；4～5 输出速度；6～7 输出扭矩；8 预测温度（减40°C）；9 状态位；10 母线电压 V；11 本机ID（兼容旧固件填零）。SDK接受公共控制命令、CB查询及遗留运行 `0x00` 的状态回复。
- **FE 完整状态 48 字节**：byte2 起连续 11 个 float32，依次是 Iq目标、Iq测量、Id目标、Id测量、位置目标、B相电流、C相电流、输出轴速度、电机侧机械角度、输出位置、电机NTC温度；46 运行模式；47 补偿位图。不是旧文档中的三相电流布局。
- **E8 身份 32 字节、E1标定完成标志**：按上节解析，反馈种类为IDENTITY/CALIBRATION，不落入普通状态解析。
- **E9 版本 12 字节**：byte2 patch、3 minor、4 major、5电机侧编码器类型，直接按无符号字节解释，不作 BCD 解码。

完整状态拒绝 NaN/Inf，未知命令拒绝解析。解析成功不代表某次请求成功匹配，事务与超时由应用处理。不能用“发送回调成功”代替设备确认。

历史0.2.0版本实测过软件复位、保存和恢复出厂，相关发现见[历史实机报告](hardware-validation-2026-10-10/REPORT.md)。这些接口不在0.3.0中提供。设备自主重启仍可能推送0xC0启动通知；该类型返回`U6913_EUNSUPPORTED`，调用方应记录后继续等待目标查询回复。

标准状态bit0为硬件使能，bit1～7分别为母线电压异常、过流、过温、过速、编码器故障锁存、预驱故障锁存、上电母线等待超时；公共头提供掩码。bit0不等于状态机就绪，bit1～4的已上报事件可能被固件清除，不应将后续零状态误当成故障原因已消除。FE本身不含这些状态位或母线电压，运行监控应同时查询CB。

## 目标固件验收
